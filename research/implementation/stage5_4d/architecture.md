# Stage 5.4D architecture

The prototype is a local read-only HTTP application with a buildless browser UI. It reuses IfcOpenShell for tessellation and the installed Plotly.js distribution for orbit, zoom, pan and picking. A browser SVG timeline handles activity rows, links and simulation. The repository's older Streamlit viewer informed the mesh rendering approach. Browser-local interaction avoids rerunning Python on each camera or timeline event. There are no external assets or services.

At startup, choose one of the two registered R0 schedules or a local application output directory. For a registered replay, the Stage 5.4C exporter authenticates the frozen schedule. For a live directory, compare pipeline evidence to the embedded scheduling evidence, bind the schedule bytes to the pipeline digest and reapply Stage 5.4C live authentication. Regenerate the expected IFC4D bundle in a temporary directory and require the submitted live artifacts to match the regenerated bytes. This protects the IFC, the viewer contract and recovered relationships even if someone edits all the submitted hashes together. The browser has no upload or arbitrary file route.

Only after authentication, tessellate the verified IFC geometry in world coordinates and serve the meshes by original IFC GlobalId alongside the verified viewer contract and selected proof fields. The browser keeps mode, filter, selection and playhead in memory. Selection joins activity IDs to GlobalIds. CPM and CP-SAT view switches read their accepted intervals. Simulation advances on the optimized date range and evaluates the accepted segments, without invoking schedule computation. The server binds to loopback and exposes a fixed set of routes. The scheduler and optimizer stay outside the frontend.
