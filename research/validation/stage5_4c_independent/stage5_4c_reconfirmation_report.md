## C1: schedule integrity

**Code review**

- **Standalone replay** accepts only the two registered Stage 5.4B.3 artifacts, by SHA-256 after CRLF-to-LF normalization.
- **The live path** requires two things:
  - the schedule bytes must equal the digest the orchestrator computed from the planning worker's output;
  - a canonical SHA-256 of the content must equal a registered accepted R0 schedule. Only the four solver runtime fields and the interpreter runtime metadata are excluded.

  - the project start;

## Findings

**Blockers:** none.

**Nonblocking**

- **N1:** solver runtime fields and interpreter version metadata are excluded from authentication, so they can be altered in a bundle without detection. They are not schedule content. If they are shown in the frontend, label them as informational.
- **Carried from the conditional review (L1–L7):**
  - **L1:** EXPRESS rules have still not been executed. `ifcopenshell.validate(express_rules=True)` needs `pytest`, which is not installed; run it in an isolated environment.
  - **L2:** holds and inspections are typed `CONSTRUCTION` in the IFC.
  - **L3:** how external viewers interpret the ISO-offset IfcDateTime values is unverified, so the frontend should use the `viewer.json` times.
  - **L4:** the R0 CPM and CP-SAT dates are identical.
  - **L5:** `viewer.json` lacks the proof, critical-path edges, calendar and resource occupancy; take them from `schedule.json`.
  - **L6 (I04):** the exporter and worker are R0-specific, which blocks any non-R0 model.
  - **L7:** segments appear only in `viewer.json`.

**Future improvements for the prototype**
- Show N1 provenance as informational.
- Read the proof, calendar and critical edges from `schedule.json`, or add them to the viewer contract.
- Mark R0 as a fixture where CPM equals CP-SAT.
- Test an external web IFC loader.
- Run EXPRESS rules in isolation.
