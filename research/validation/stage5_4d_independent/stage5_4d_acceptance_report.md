**Note on test sensitivity.** Two harness effects initially produced false negatives. Both were diagnosed and are not defects:
- **3D picking.** Clicks need a short dwell. Some edge pixels register hover but not a click: in a diagnostic, the column was selected at 2 of 5 edge points and the beam at 4 of 5. Interior points select reliably. This is recorded as limitation L1.
- **Orbit.** Drag detection needs settle time. With dwell it passed 4 of 4 in the diagnostic and in all three workspaces.

## 4. Schedule visualization (Priority 4)

- **Gantt dates and arrows.** I recomputed every bar position from the accepted schedule. I also recomputed all 28 arrows from the accepted dependency list, using true finish-to-start x-coordinates. All match.
- **Short activities.** 13 activities of 10–60 min would be narrower than 3 px, so they are drawn at a 3 px minimum (about 66 min at full-chart scale). They remain distinguishable, and the exact start and finish appear in the tooltip and detail panel. However, the widening is disclosed only in the README, not in the UI (L2). Durations are therefore not misrepresented in any text, only visually rounded up.
- **Playback.** It is labelled as an activity simulation with physical progress unverified. "Completed" in the model legend means "all linked activities reached scheduled finish". Nothing implies measured or verified progress.
- **Critical path.** It is shown only in CPM mode, as red bar outlines on the 7 accepted critical activities, and the tooltip says "CPM critical". The note "CPM and CP-SAT dates coincide in this R0 fixture" is shown. Bar geometry is identical across modes, and no optimization gain is claimed. There is no critical-edge overlay (U3).

## 6. Findings

### 6.1 Blocking defects

None.

### 6.2 Nonblocking limitations

| ID | Limitation |
|---|---|
| L1 | 3D picking has click dead zones near some element edges, where hover registers but the click does not select. Interior clicks work, and the keyboard-accessible element buttons give full coverage. |
| L2 | The 3 px minimum bar width (13 activities shown at about 66 min-equivalent) is not disclosed in the UI. |
| L3 | The safety banner, approval status and the "CPM and CP-SAT coincide" note are static HTML, not data-derived. They are correct only because the server refuses to start unless 88 PENDING, eligibility false and R0. If eligibility logic or non-R0 inputs are ever introduced, these must become data-driven. |
| L4 | The " CET" suffix is hard-coded. It is correct for the January R0 dates, but a schedule crossing a DST boundary would mislabel CEST. |
| L5 | The active-bar outline (`#9a4900`) is not in the Gantt legend and is close to the Inspection colour. Its selector (`.row.active .bar`) outranks `.bar.critical`, so in CPM mode a critical activity's red outline is hidden while that activity is active during playback. The tooltip still states "CPM critical". |
| L6 | The frontend is hard-wired to R0 (3 GlobalIds, 2 ticks). This is consistent with the authorization, and inherits 5.4C limitation I04. IFC EXPRESS rule validation is still not run. |

### 6.3 Recommended usability improvements

| ID | Recommendation |
|---|---|
| U1 | Add a caption such as "bars under N min drawn at minimum width; see tooltip for exact times". |
| U2 | Add "Active" to the Gantt legend in a hue distinct from Inspection, and keep the critical outline visible while active (for example, a separate glow or dash). |
| U3 | Optionally add a critical-edge overlay in CPM mode. |
| U4 | Format the timezone label via `Intl` (`timeZoneName: "short"`) instead of a literal. |
| U5 | The sticky banner overlaps the top of the playback panel when scrolled; add scroll padding. |
| U6 | Add a hover cursor or tooltip on mesh edges to reduce picking ambiguity. |
